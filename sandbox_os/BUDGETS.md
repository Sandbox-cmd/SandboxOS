# BUDGETS: six parts, one job each, and the tripwire against bloat

Each part has one job said in one sentence and is readable whole. Parts depend downward only, in this order: store; partner; pages; hosts; command; tests. A cycle fails the build. The limits are a tripwire against bloat, not a goal: each was set from its part's measured size, and a limit moves only with a new date and a new reason, which the release check compares with the release before. Each row's reason says in a clause what its limit is for; the longer reasons written while the tool was built, through 11.0.0a13, stay with its maker. Data tables (the strings table, the fonts under `sandbox_os/pages/fonts/`) are excluded from every count and measured apart.

| part | job, in one sentence | paths | limit | unit | date | reason | bytes |
|---|---|---|---|---|---|---|---|
| store | keeps every line of the record as plain JSON lines, each chained to the one before, and answers what the other parts ask from an index it can rebuild from the files | `sandbox_os/store/**/*.py` | 4300 | lines | 2026-11-10 | the record is what every other part trusts, so the code that keeps it stays small enough to read whole |
| partner | holds the charter, the book and the grants as the partner's standing instructions, which the hosts place | `sandbox_os/partner/**` | 6134 | words | 2026-11-08 | the charter and the book are placed whole in every session, so their words stay few enough to read at its start | 30720 (`wc -c` of `charter.md` and `book.md` together): Codex carries both pages whole in its instruction block, at most 30 KiB of its 32 KiB, so a project keeps about 2 KiB |
| pages | constructs every view from the lines on demand, every count computed at render, each view also a file, served on the loopback address | `sandbox_os/pages/**/*.py`, `sandbox_os/pages/**/*.html`, `sandbox_os/pages/**/*.css`, `sandbox_os/pages/**/*.js` | 4700 | lines | 2026-11-10 | every view is built from the lines when it is opened, so the code that builds them stays small enough to read whole |
| hosts | one adapter per host that writes the host's deny rules and sandbox first, places the instructions within the host's limit, observes with hooks and reads back what the host asked | `sandbox_os/hosts/*.py` | 700 | lines each | 2026-11-10 | each adapter writes a host's rules and places the partner's instructions, so each file stays short enough to check line by line |
| command | installs, runs the onboarding flow, updates with held files, self-checks and seals a release | `sandbox_os/command/**/*.py`, `sandbox_os/__init__.py`, `sandbox_os/__main__.py` | 5222 | lines | 2026-11-14 | the commands a person types, the update and the release's seal stay small enough to read whole before trusting them |
| tests | one test per promise and consent line, the eight bypasses and the budget test, each naming what it guards | `tests/**` | uncounted | | 2026-10-30 | the tests are not counted, so a guard is never cut to make room |

Excluded from every count and measured apart, by name: `sandbox_os/pages/strings.tsv`, `sandbox_os/pages/locales.tsv`, `sandbox_os/pages/fonts/**`, `sandbox_os/command/release.pub`. In the source tree, the tree's own files at the root (`BUDGETS.md`, `LICENSE`, `README.md`, `CHANGES.md`, `CONTRACT.md`, `CLAUDE.md`, `AGENTS.md`, `.gitignore`, `.gitattributes`), the public shelf's scaffolding (`shelf/**`) and the packed releases (`dist/**`) belong to the tree, not to a part; of them a release carries `LICENSE`, `BUDGETS.md` and `CHANGES.md`. In an installed copy, those three and the release's own files (`suite-summary.json`, `release-checks.txt`, `MANIFEST`, `MANIFEST.minisig`) sit beside the code and belong to no part. The first page, which stays in the source tree, is held to 800 words (`wc -w`) by the release's licence check, outside this table.

Counting is `wc -l` over the part's files, comments and docstrings included; words are `wc -w`. A part over its limit, a shipped file that belongs to no part, or a part whose paths match nothing fails the build: in the source tree the budgets and cycle test holds it, and in an installed copy the self-check reads this page and counts the installed files the same way.
